Inside ResearchIT Problem, decisions & engineering

A feed for a person
with more than one interest.

Designed, built, deployed, and evaluated independently.

Why I built it

Save papers about language models and robotics, and a single averaged profile can lose what made each interest distinct. I wanted recommendations that made room for both.

What I learned

Balancing the candidate pool isn’t enough. The final ordering matters too. Interest quotas and diversity within each interest help keep one topic from taking over.

The engineering, if you’re curious +

BGE-M3 retrieves semantic neighbors from Qdrant. SQLite FTS5 adds lexical matches. Reciprocal rank fusion brings the lists together, and a cross-encoder reranks a small candidate set.

The discovery feed uses saved-paper interests, quota allocation, and diversity within each interest. The default feed scorer is heuristic; the optional learned model is a separate experiment.

Prompt Memory

A clearer prompt that still means what you meant.

A browser extension that turns a rough request into a reviewable rewrite, using context from the conversation. You choose what to apply and what it remembers.

My part The in-chat experience, approval-gated memory, rewrite policy, and evaluation.

See an example ↓Source & setup ↗
Inside Prompt Memory Recorded example, contribution & evaluation

A better prompt should
still sound like your request.

Co-built with a collaborator. My focus: the in-chat experience, approval-gated memory, rewrite policy, and evaluation.

The problem

A prompt can look polished and still change what you meant. Invented deadlines, extra requirements, or lost constraints are real failures.

The decision

Show the rewrite before applying it. Keep the user in control. Write passive memory only after an approved rewrite is applied.

A little more on my contribution +

I built most of the in-chat extension, including the rewrite card, context library, and voice review, alongside the approval-gated memory and rewrite evaluation work. My co-builder started the project and led the landing page, analytics dashboard, sign-in, and release work.

The 82-case corpus spans 21 failure categories, including numerical fidelity, negative constraints, language preservation, and context injection. A larger held-out evaluation remains a useful next step.
